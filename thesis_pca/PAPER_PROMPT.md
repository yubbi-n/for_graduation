## 프롬프트

나는 학부 졸업논문을 쓰고 있어. 실험은 모두 끝났고, 아래 실험 설계와 결과를 바탕으로 논문 작성을 도와줘.

### 작성 원칙
- 수치는 아래 "결과"에 있는 값만 사용해. 없는 수치(표준편차, 다른 데이터셋, 다른 모델 결과 등)를 만들어 내지 마. 필요하면 나한테 물어봐.
- 한국어 학술 문체(~이다, ~하였다)로 써 줘. 그림 축 라벨은 영문이므로 본문에서 그림을 언급할 때는 "그림 1"처럼 번호로 부르면 돼.
- 해석이 결과에서 바로 나오는 것인지, 추론이나 가설인지 구분해서 써 줘.
- 연구 질문:
  - RQ1. MNIST 공분산행렬의 고유값은 어떤 크기 분포와 감쇠 구조를 갖는가? (그림 1, 그림 2)
  - RQ2. 주성분 수 k에 따라 분류 정확도와 학습 시간은 어떻게 변하며, 원본 대비 얼마나 줄여도 성능이 유지되는가? (그림 3)
  - RQ3. 누적 설명분산 R_k와 분류 정확도는 어떤 관계인가? (그림 4가 핵심 근거)

### 주제
주성분 분석(PCA)의 고유값 구조에 따른 차원 축소와 분류 성능 분석

### 실험 설계
- **데이터:** MNIST (`fetch_openml("mnist_784", version=1)`). 표준 분할로 앞 60,000개를 train, 뒤 10,000개를 test로 사용하였다. 784차원(28×28)이다.
- **전처리:** 픽셀값을 255.0으로 나누어 [0, 1]로 정규화하였다. 표준화(StandardScaler)는 적용하지 않았다.
- **PCA:** train에만 fit하고 test에는 transform만 적용하였다(데이터 누수 방지). `PCA(n_components=784, svd_solver="full")`로 한 번 fit한 뒤, k개 주성분은 앞 k개 성분(`components_[:k]`)을 사용하였다. 이는 PCA(k)를 따로 fit한 것과 동일하다. 고유값 λ_i는 공분산행렬 Σ = XᵀX/(n−1)의 고유값이고, r_i = λ_i / Σλ_j, R_k = Σ_{i≤k} r_i 이다.
- **분류기:** 다중 클래스(multinomial) 로지스틱 회귀, `solver="lbfgs", max_iter=1000, C=1.0, random_state=42`. 모든 k에서 하이퍼파라미터를 동일하게 유지하였다(통제변수).
- **실험 조건:** k ∈ {2, 5, 10, 20, 50, 100, 200, 784}와, 누적 설명분산이 처음으로 80/90/95/99% 이상이 되는 k(44, 87, 154, 331)를 합한 12개 조건. k=784는 PCA를 적용하지 않은 원본 픽셀이다.
- **측정:** test 정확도, train 정확도, LR 학습 시간(`time.perf_counter`, 3회 반복 평균), 차원 감소율 1 − k/784.
- **난수 시드:** 42로 고정.
- **실행 환경:** AMD EPYC 7282 16-Core Processor(16코어 32스레드, 공용 서버, 부하가 낮을 때 실행), BLAS 스레드 8개. Python 3.11.18, scikit-learn 1.9.1, numpy 2.4.6, pandas 3.1.0, matplotlib 3.11.2.

### 결과 1: 고유값 구조
- 고유값 총합(전체 분산) Σλ_i = 52.73
- 상위 주성분:

| 주성분 | λ_i | r_i | R_k |
|---:|---:|---:|---:|
| 1 | 5.1169 | 0.0970 | 0.0970 |
| 2 | 3.7414 | 0.0710 | 0.1680 |
| 3 | 3.2527 | 0.0617 | 0.2297 |
| 4 | 2.8416 | 0.0539 | 0.2836 |
| 5 | 2.5671 | 0.0487 | 0.3323 |

- λ₁/λ₁₀ ≈ 4.1, λ₁/λ₁₀₀ ≈ 96.5. 고유값이 빠르게 감소한다.
- 누적 설명분산: R_10 = 0.488, R_50 = 0.825, R_100 = 0.915, R_200 = 0.966
- 하위 400개 성분(385~784번)의 설명분산 합은 0.0052(0.52%)에 불과하다. 참고로 하위 384개(401~784번)의 합은 0.0042(0.42%)이다.
- 72개 고유값이 10⁻¹⁰ 미만(713번 이후)으로 사실상 0이다. train에서 모든 이미지가 값 0인 가장자리 픽셀이 67개이므로, 그만큼은 정확히 0인 고유값이 되고 나머지 일부도 수치적으로 0에 가깝다. 따라서 공분산행렬의 실질 랭크는 약 712이다.

### 결과에서 관찰된 점
- 정확도는 k가 작을 때 급격히 오르다가 k≈44(R_k 80%) 이후 완만해진다. k=2→20 구간에서 0.446→0.881로 오르고, k=44→784 구간에서는 0.910→0.926으로 1.5%p만 오른다.
- k=87(R_k 90%)에서 test 0.9194로 원본보다 0.64%p 낮지만, 차원은 89% 줄고 학습은 약 14배 빠르다(1.53초 vs 21.54초).
- k=200에서 test 0.9261로 원본(0.9258)과 같은 수준이고, 학습은 약 6.6배 빠르다.
- k=331(R_k 99%)의 test 정확도(0.9252)는 k=200(0.9261)보다 낮다. 설명분산이 커진다고 분류 정확도가 계속 오르지는 않는다.
- k≤100에서는 train−test 정확도 차이가 −0.013~+0.001로 거의 없다(k≤50에서는 test가 오히려 약간 높다). 이후 차이가 커져 원본 784차원에서 0.0131로 가장 크다. 작은 고유값 성분이 test 성능에는 거의 기여하지 않고 train 적합만 높인다고 해석할 수 있다(추론).
- 학습 시간은 k=331까지 완만하게 늘다가(4.55초), 원본 784차원에서 21.54초로 크게 늘어난다.
- R_k와 test 정확도는 단조 비례하지 않는다. R_k 0.17→0.80 구간에서 정확도가 크게 오르고, 0.80 이후에는 R_k가 0.2 늘어도 정확도는 약 1.5%p만 오른다(그림 4).

### 해석 시 주의할 점 (한계로 쓸 수 있음)
- 원본 784차원의 test 정확도는 실행 환경(스레드 수, CPU)에 따라 0.9258–0.9262로 미세하게 달라졌다. 원본은 특징 간 상관이 강해 최적화가 수치적으로 민감하기 때문으로 보인다. 다른 k는 환경과 무관하게 소수 넷째 자리까지 같았다.
- 학습 시간은 실행 환경에 의존한다. 같은 서버를 고부하일 때 사용한 실행에서는 k=331, 784의 학습 시간이 각각 146초, 412초로 크게 늘었다. 보고한 값은 부하가 낮을 때 잰 것이다.
- 데이터셋 1개(MNIST), 분류기 1개(로지스틱 회귀), 단일 train/test 분할, 단일 시드로 실험하였다. 정확도에 대한 반복 실험이나 신뢰구간은 없다.
- test 10,000개 기준으로 정확도 0.0001은 샘플 1개다. k=200과 k=331의 차이(0.0009)는 9개, k=200과 원본의 차이(0.0003)는 3개에 해당한다. 단일 시드이므로 이 정도 차이는 유의하다고 단정할 수 없다. 결과 장에는 수치만 적고, 논의·한계에서 이 단서를 붙인다.
- 표준화 없이 [0, 1] 스케일에서 PCA를 적용하였으므로, 표준화를 적용하면 고유값 구조와 결과가 달라질 수 있다.
- 하이퍼파라미터(C=1.0)는 모든 k에서 고정하였다. k별로 튜닝하면 결과가 달라질 수 있다.
